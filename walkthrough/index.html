docaxioms 是什么，怎么组织的

本导读基于提交 d840742。文中的 文件:行号 都指这个版本；代码以后改了，行号会漂移，函数名不会。

它是什么

docaxioms 是一个本地运行的命令行工具（Node.js，纯 JS），检查一个软件项目的文档是否还和代码、和 owner 的决定对得上。它不写文档、不调用模型，只做确定性的检查：同样的仓库，跑几次结果都一样。

它的每条规则都从一组锁定的公理推出来（core/AXIOMS.lock.md：A0–A8 九条公理、M1–M4 四条方法），每个检查名后面的括号里写着它依据哪几条。

能保证的

链接不断、路径存在、钉住的代码没变、决策有落地点、历史记录没被改写、文档在预算内……都是机器能精确判断的性质。

保证不了的

文字描述是否真的符合代码行为、决策是不是 owner 本意。这些靠人和定期的 garden 审计（A6：门禁只保证它判断的那一条）。

不做的

不自动改写文档。代码变了，它只指出哪里要复核；改不改、怎么改，由人或 agent 决定（A0）。

  3. 17 项检查：每项判定什么、代码在哪、哪条测试证明它会失败。

三层结构：公理 → 规范 → 检查

公理与方法core/AXIOMS.lock.md：A0 owner 是权威、A2 依赖会过期、A4 手抄的副本会分叉、A5 记录不可改写、A6 门禁只保证它的判断、A7 门禁要精确……锁定，只有 owner 能改。
↓ 推出
操作规范core/GUIDE.md（改了什么就更新哪份文档、怎么退役文档、profile 字典）和 core/GARDEN.md（只读审计协议）。纯文本，不点名任何项目、工具或语言（AD-2），由测试守住。
↓ 机器能判断的部分，做成
检查src/check.mjs 里的 17 项（15 项 gate 会让命令失败，2 项 aid 只提醒），加上项目自己的 projectChecks。

接入的项目会把 core/ 原样复制一份到自己的 docaxioms/ 目录，并在 docaxioms.json 里记下每个文件的 SHA-256。之后谁改了这份副本，检查就会失败（A4）。

一次 docaxioms check 的全过程

1. 读 profileloadProfile() bin/docaxioms.mjs:24：读 docaxioms.json，原样交给引擎。check 不在这里拒绝错误的 profile；pin 和 garden 会（strict: true）。
↓
2. 校验 profile，得到可用部分profileProblems() 列出问题；usableProfile() 剔掉出错的设置，其余照用 src/profile.mjs:114, 123。只有 profile 根本不是 JSON 对象时，所有检查都不运行、全部报 error。
↓
3. 建仓库视图 project()src/check.mjs:93。确定仓库边界（inside()，含符号链接）、所有读取的唯一入口 read()、文件清单 all（来自 git ls-files，没有 git 时遍历目录）、现行文档 currentDocs（除去 history 和 core 的 .md）、代码文件 code、链接解析 targetOf()。每份 Markdown 只解析一次并缓存。
↓
4. 逐项运行 17 项检查每项经 runCheck() :768 运行：返回发现（problems）和说明（notes）；抛出异常时记成 error，后面的检查照样跑（A6）。
↓
5. 项目自己的检查profile 配了 projectChecks 时，从仓库内的那个文件 import，导出必须是检查的列表 :791。
↓
6. 打印与退出码每项一行：ok、FAIL、aid、note 或 ERR bin/docaxioms.mjs:57。

退出码规则

来自 bin/docaxioms.mjs:66-68：

errored = 有任何一项检查运行出错
failed  = 有 gate 级发现（或开了 --strict-aids 时 aid 也算）
退出码  = errored 或（failed 且没有 --report） ? 1 : 0
情况默认--report--strict-aids
全部 ok，或只有 note000
只有 aid 的发现001
有 gate 的发现（FAIL）101
有检查运行出错（ERR）111
为什么出错时连 --report 也失败：一项检查没能运行，就不知道它本该发现什么。把它当作通过，等于让检查静默失效（A6）。

四类内容（M1）：检查为什么对不同文档区别对待

方法 M1 把文档里的每句话分成四类，很多检查只对其中一类生效：

类别含义在模板里对检查的影响
K1 记录过去的事，带日期，永不改写，错了只能加勘误docs/log.md、docs/history/history 只允许改链接目标或追加勘误；不检查路径、命令（记录可以提到已删除的东西）
K2 规范必须成立的事，权威是 owner 的决定docs/decisions.md决策号唯一、有落地点、落地段落提到它
K3 描述软件现在是什么样，会随代码过期README、设计文档、docs/README.md路径、命令、pin、演化措辞都只查这一类（descriptionDocs() src/check.mjs:298）
K4 计划将要做的事docs/plan.md、docs/research/可以提到还不存在的路径和命令；开放的调研必须被计划里的开放条目链接

阶段卡 CURRENT.md 混合了描述和计划，按预算单独管（不超过 45 行、4000 字符）。

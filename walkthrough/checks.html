17 项检查

全部定义在 src/check.mjs 的 CHECKS 数组里（第 318 行起），按数组顺序运行和打印。每项是一个对象 { name, axioms, level, run(p) }，run 接收 project() 建好的仓库视图 p，返回发现的列表，或 { problems, notes }。

gate 与 aid（M2）

gate 15 项

判断的就是性质本身，而且精确：有发现就让命令失败（退出码 1）。例如“链接目标存在”。

aid 2 项

只是信号，会有误报：打印发现但不失败，除非 --strict-aids。先在真实项目上量信噪比，才可能升为 gate。

note

检查没能按配置完整比较时（例如找不到比较基线），打印说明它少查了什么，显示 note 而不是 ok。不算发现，不失败。

项目自己的检查（projectChecks）

profile 里写 "projectChecks": "tools/doc-checks.mjs"，这个模块默认导出一个检查列表，格式和内置的一样：

export default [
  {
    name: "every public endpoint is documented",
    axioms: "A2",
    level: "gate",          // 或 "aid"
    run: (p) => {           // p 就是 project() 的仓库视图：p.read、p.currentDocs、p.markdown……
      return [];            // 发现的列表；或 { problems, notes }
    },
  },
];

加载规则（check.mjs:791-810）：文件必须在仓库内、是普通文件（不能经符号链接指到仓外）；导出必须是数组，每项有字符串 name 和函数 run；否则整组不运行，并报一条 “project checks load” 错误。每项运行时同样经 runCheck()，一项出错不影响别的。项目自己的 profile 键要以 x- 开头，检查里通过 p.profile["x-…"] 读取。

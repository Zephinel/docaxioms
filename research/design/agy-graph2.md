# 第二轮讨论答复：反射弧模型与六项分歧收敛

结合 `main` 源码（`src/pins.mjs`、`src/check.mjs`、`src/markdown.mjs`、`src/garden.mjs`、`bin/docaxioms.mjs`、`test/self.test.mjs`）、公理与 `docs/decisions.md`（AD-1..AD-7），以及第一轮两份答复逐条回应如下。

---

## 1. 显式文档 pin 是 gate 还是 aid

**表态：拆成两层谓词——“目标/锚点存在 + 无依赖环”直接做 `gate`；新增的“Markdown `#anchor` 内容哈希变化”以及一切“传递影响”先做 `aid`，跑够实证再升 `gate`。**（修正我第一轮把文档散文哈希与代码切片哈希一刀切等同的说法。）

理由：
1. **源码现状需先厘清两层开关**：`src/check.mjs:480` 中现有 pin 检查已是 `gate`，且 `test/docaxioms.test.mjs:137-138` 已把 `<!-- pin: README.md#L1-L2 -->` 当 `gate` 测；而 **AD-7 管的是本仓库自身的合并阻断集**（`test/self.test.mjs:12-36` 用独立白名单只让链接、路径、命令、axiom 锁和 `missing/outside-root` 的死 pin 阻断合并，`changed` 在本仓库本就只报告）。因此无论对消费项目定什么级别，本仓库在外部项目跑满“10 次相关改动 + 3 次值得改文档的发现”（`docs/decisions.md:12`）之前，绝不进 `self.test.mjs` 的阻断集。
2. **为什么 `#anchor` 文档哈希比代码行段更容易触发 A7 噪音**：10 行代码改一字多半改了行为，但上游 Markdown 章节改标点、修错字、润色过渡句都会改变 SHA-256，而下游摘要往往无需改动。其检查谓词只是“上游字节变了”，不完全等于“下游摘要失真了”（M2）。
3. **精确切分**：
   - **Pin 指空（文件或 `#anchor` 不存在、越界）与文档 pin 成环**：100% 是结构错误，零误报 $\rightarrow$ **`gate`**（与 `links and anchors resolve` 同级）；
   - **Markdown `#anchor` 内容哈希失配**：先以 **`aid`** 统计“上游改字时下游真需改字的比例”，高信噪比被证实后再并入阻断；
   - **传递下游提醒（`A -> B -> C` 中的 `C`）**：谓词只是“祖先变了”，永远是 **`aid`**。

## 2. 提前截断怎么实现（两方是否一致，剥注释外还要什么）

**表态：两方底层机制一致，分别说了“稳态数据表示”和“瞬态遍历条件”，必须合起来才没有漏洞。**

- **一致之处**：我说的“对 Markdown 锚点算哈希时剥离其中的 `<!-- pin: ... -->` 注释”（复用 `src/markdown.mjs:93` 的 `htmlComments` 偏移），正是 codex 说的“分开计算正文输出与复核元数据”在零外部状态库下的具体实现——正文即输出值，pin 注释即入边复核戳。
- **仅剥注释还不够，还必须补齐 3 个条件**：
  1. **中游未复核时禁止假截断（引入三态而非二态）**：`A` 刚改而 `B` 尚未复核时，`B` 的正文当然还没变，`C` 钉住 `B` 的哈希在磁盘上仍是相等的。此时影响报告绝不能宣布 `C` 已截断，而必须标为 **`pending-upstream`（挂起待定）**；只有当 `B` 完成了复核刷新（`B` 的入边恢复 `ok`）**且** `B` 去注释后的正文哈希未变时，`C` 才真正触发 early cutoff 归为 `clean`。
  2. **按“入边”而非按“节点”判定（处理菱形依赖 `A -> B -> C` 且 `A -> C`）**：`B` 正文未变只截断 `B -> C` 这一条边；只要 `C` 还有另一条入边 `A -> C` 处于失配或挂起状态，`C` 仍为待复核。用“存在任一脏入边则脏”求不动点即可天然满足。
  3. **只剥 pin 元数据注释，且 `B` 自身增删 pin 不传染给 `C`**：只剥匹配 `PIN_ATTEMPT`（`src/pins.mjs:19`）的注释，保留代码块与 `<a id="...">`；至于 codex 提到“依赖边增删另行触发复核”，应只触发 **`B` 自身**的复核（新增未刷新的 pin 本来就会在 `B` 报错），不应改变 `B` 对 `C` 的正文哈希，否则给 `B` 补一条上游证据反而把下游全震脏。

## 3. 复核证据

**表态：日常 K3 / 文档 pin 不造“复核声明表单”，坦诚按 A6 承认语义核对“靠注意力”；用收紧 CLI 盲刷与差异可视化托底；只有 K2 / 治理变更在闸门档位用硬件签名作真证据。**

理由：
1. **同权限域内的自填证据都是伪证据（A6、A7）**：无论是强制提交信息写 `Reviewed-pin:`，还是维护一份复核记录文件，在开发者与 Agent 同一身份下，脚本自动填一行声明与自动跑 `pin --write` 成本完全相同（方案第 539 行已写明：“作者自己写的 `reviewed: true` 只算声明”）。强加仪式既不增加可信度（`core/GUIDE.md:53`：“No check holds that a description is right”），还会制造填表疲劳（A7）。
2. **最小可行的真实改进（零新文件，堵住现存盲刷口）**：
   - **收紧 `bin/docaxioms.mjs:80` 的 `--write --all`**：当前 Agent 一条 `docaxioms pin --write --all` 就能不看任何文件把全仓过期 pin 刷绿；应移除 `--write --all`（只保留 `--relocate` 可全仓无损平移，`--write` 必须逐文件 `--file` 或逐条 `--pin`）。
   - **让 Git diff 与影响报告充当公开审阅面**：Git 提交里 `@old -> @new` 的改动行本身就是“谁在哪次提交声称核对过”的 K1 记录；在 `check` / PR 影响报告（方案第六节第 3 项）中，把**“刷新了 `@hash` 但所在段落散文一字未改”**的条目单独列出，让审阅者一眼聚焦“这里声称无需改字，真的吗？”。
   - **真证据只留给高风险边界**：配了本地闸门时，K2 决策与治理文件变更由 owner 的 FIDO2 物理触摸签名绑定 `(B, C)` 快照（方案 L4 / G12），不往日常散文维护里下放重型审批。

## 4. “单根错觉”：owner 的“任务完成只改一处”在什么范围内成立

**表态：“全局单根”不成立（代码、决策、任务不能合一），但“分域单根”与“收尾时刻单点触发台账流转”完全成立。**

- **完全成立的两个范围**：
  1. **任务收尾的台账与生命周期层（K4 $\rightarrow$ K1 / 索引 / 提醒）**：假设编码期间代码与对应的 K3 描述已同步写好，到了“宣布任务完成”这一步，目前 `core/GUIDE.md:36` 需要手工串联多处（改计划、迁 `research/` 进 `history/`、加横幅、改旧链接、改阶段卡）。引入图与收尾命令后，**只需对任务做一次关闭动作**，工具即可自动归档关联 `research/`、补横幅、重写全仓指向旧路径的链接、重算索引（G20），并点名引用了该任务的 `CURRENT.md` 段落待更新——这正是 owner 想要的体验。
  2. **单一事实源的局部投影子图（M3）**：例如改一处 `ownership.md` 自动重算 `allowed_signers` 与 `CODEOWNERS`；改一处源表自动重算汇总索引并标出 pin 了它的摘要段落。在同一事实域内，“只改权威源一处，下游自动生成或精准点名”完全成立。
- **不成立的范围（A0、M1）**：不能指望“只把 K4 任务标为完成”就自动推出 K3 架构描述或 K2 决策该怎么改；一次真实的功能交付，**代码（实然）、决策（应然，若有）、任务状态（工作态）**各自是自己子图的根。

## 5. 反射弧模型的审视：失真处、分界判据与抗习惯化机制

### 成立与三处失真
- **成立之处**：把低风险机械同步下沉给“脊髓”，把稀缺注意力留给“大脑”（A3、A7），事后向大脑汇报已做动作与待决清单，分工极佳。
- **三处失真**：
  1. **触发时机失真**：生物反射是连续实时的；但文件编辑中途（半成品状态）绝不能由后台守护进程“反射式”改写仓库文件（会与编辑器冲突并制造脏状态，见方案第七节）。反射只能在**离散快照节点**（显式 CLI 命令、提交前钩子、闸门接收时）触发。
  2. **多跳依赖失真**：生物反射弧是单跳定型回路；文档 DAG 多跳传播遇到散文中间节点 `B` 时，脊髓**必须停下等大脑审完 `B`**，才能决定是否向 `C` 继续传导，不能越过 `B` 直接动作。
  3. **“习惯化”主体失真**：生物习惯化是神经回路自己减弱反应；但门禁若因高频触发就“自动静默放行”，直接违背 A6（门禁不再保证谓词）！文档系统里习惯化发生在**人的注意力**（A7），工具的职责是**消除假刺激以阻止人习惯化**，绝不是自己装瞎。

### 脊髓（自动写盘）与大脑（人工/Agent 审决）的四条分界判据
仅当**同时满足**以下四条时，才允许归入“脊髓”自动落盘；缺任一条，脊髓只生成拓扑序待办或候选补丁，由“大脑”确认：
1. **单值确定性**：同一仓库快照下输出字节唯一确定（纯函数）；
2. **零新语义主张（A0）**：不增删改手写散文含义（例如只改移动后的链接目标而不改正文，可用 `withoutLinkTargets` 精确验证）；
3. **无歧义**：多解时立即中止并上报（如 `pins.mjs:192` 的 `ambiguous-move`）；
4. **可重演 / 不毁史（A5）**：结果可从权威源重算，且绝不静默覆盖历史记录正文。

### “抗习惯化”的落地机制
1. **同源折叠（合并刺激）**：`A` 变导致 `B -> C -> D` 受影响时，报告合并为 1 条根因（列出 `B` 待审，`C, D` 折叠为 `+2 downstream waiting on B`），禁止刷屏；
2. **提前截断 + 去注释哈希**：截断中游未改字时的无效级联；
3. **基于 Git 历史的离线信噪比计量（落实 M2 / AD-7，无需后台状态库）**：统计某条 `aid`（如某条 `codeToDocs` 规则或 `#anchor` pin）在历史提交中触发时，下游文档实际跟着修改正文的比例（命中率）。长期低命中率的规则予以收窄、拆分或移除，达标者才允许提请升为 `gate`。

## 6. 第一版收敛（合并后的 4 项最小可行清单）

不新建平行图配置，全部生长在现有模块上：

1. **Markdown 锚点 pin 与去注释哈希（建边 + 提前截断底座）**
   - **谓词**：① 目标文件与 `#anchor`（标题 slug 或 `<a id>`）存在，且文档间 pin 有向图无环；② 目标切片剥除 `<!-- pin: ... -->` 注释并归一 `\r\n` 后的 SHA-256 前缀匹配 `@hash`（同文件内唯一同哈希章节改名判为 `moved`）。
   - **级别**：① 目标缺失、格式错误与成环为 **`gate`**；② 新增的 Markdown `#anchor` 内容哈希变化首版设为 **`aid`**（现有代码/行段 `#Lx-Ly` 保持 `gate`；本仓库守 AD-7，仅死路径/死锚点阻断）。
   - **复用机制**：`src/pins.mjs`（`parsePinComment`、`inspectPins`、`syncPins`、`--relocate`；顺带收紧 `bin/docaxioms.mjs` 的 `--write --all`）与 `src/markdown.mjs`（`passage(anchor)`、`explicitAnchors`、`htmlComments`）。

2. **派生依赖图与拓扑影响报告（反射中枢：区分直接失效与挂起待定）**
   - **谓词**：从内存边表反向求闭包，将直接上游失配标为 `direct-stale`，将仅祖先失配标为 `pending-upstream`（中游未复核时不假截断；中游刷新且正文哈希未变时自动截断），按拓扑序输出并折叠同源下游，同时高亮“仅刷 `@hash` 未改散文”的条目。
   - **级别**：**`aid`**（集成进 `check` 辅助输出与 `garden --json` 报告，不阻断退出码）。
   - **复用机制**：`src/check.mjs`（`project()`、`decisionRows()`、`changedFiles()`、`codeToDocs`）、`src/pins.mjs`（`inspectPins()`）与 `src/garden.mjs`（`gardenManifest()`）。

3. **文档与研究退役的单点机械联动（脊髓动作试点）**
   - **谓词**：显式命令将目标迁入 `history.dir`、补齐 `history.banner`、按反向链接重写仓内链接目标，保证迁移前后 `withoutLinkTargets` 正文不变且全仓断链为零，同时打印需人工改散文的引用位置（如 `plan`、`CURRENT.md`）。
   - **级别**：显式 CLI 写入动作；产物由现有 **`gate`**（断链、`history` 横幅与只改链接目标门禁）验收。
   - **复用机制**：`src/check.mjs`（`p.links()`、`resolveTarget()`、第 358/514/645 行三项现有门禁）与 `src/markdown.mjs`（`withoutLinkTargets()`）。

4. **最小确定性生成物校验（落地首个 G20 节点，靠 M3 减边）**
   - **谓词**：已登记生成物的磁盘内容严格等于其生成器对当前仓库输入的输出（内容未变不重写磁盘），且纯生成文件统一排除出 K3 散文检查与 `garden`。
   - **级别**：消费项目配置后为 **`gate`**（纯字节相等谓词，符合 A4、A6、M2）；本仓库在完成 AD-7 实证前只报告。
   - **复用机制**：`src/profile.mjs`（`SCHEMA` 与 `usableProfile`）、`src/check.mjs`（`descriptionDocs()` 豁免集与 `core` 哈希式的字节比对框架）及 `src/garden.mjs`。

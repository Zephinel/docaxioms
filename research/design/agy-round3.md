## 二、对定稿六项新裁决的逐条表态（按风险严重度排序）

### 1. 策略取自基线的引导与 break-glass —— **有条件同意**（风险最高）
- **公理与源码依据**：
  - 当前 `bin/docaxioms.mjs:23-27` 与 `src/check.mjs:664-676` 直接读工作树的 `docaxioms.json` 并动态 `import(profile.projectChecks)`，候选 PR 可同时改 `core.files` 哈希、豁免项与扩展检查来绕过（`README.md:62` 已承认）。策略取自基线是堵漏正解（A6）。
- **必须补齐的条件**：
  1. **不能把“正常策略演进 / `docaxioms update`”混同为“坏策略 break-glass”**：对照 `src/manage.mjs:74-83` 与 `src/check.mjs:266-286`，常规 `docaxioms update` 必然修改 `docaxioms.json` 的 `core.version`/`commit`/`files` 哈希以及 `docaxioms/`；在 `0.x` 阶段（`README.md:7`），升级 CLI 版本还常需同步改 `package.json`/lockfile 与 `docaxioms.json`。若该通道限定“只允许改策略文件”，常规升级就会二次死锁；若都贴 break-glass 标签，会钝化审批警觉（A7）。应定义为**“治理变更通道”**，允许受保护的治理白名单文件（策略、`docaxioms/`、依赖锁、验收 workflow）原子协同变更，要求 owner 审批并用候选策略自检。
  2. **白名单校验者必须独立于候选 PR**：若判定“该 PR 只改了治理白名单”的逻辑写在仓库自带的 `.github/workflows/check.yml` 里，候选 PR 顺手改 workflow 即可伪造通道。须依赖基线 workflow 或平台级 Required Workflow（L4）。

### 2. 汇总视图不入库 —— **有条件同意**
- **公理与源码依据**：
  - 彻底消灭多 PR 在 `plan.md`/`decisions.md`/`log.md` 上的合并队列冲突，且符合 M3（唯一维护位置，生成视图不必入库）。
- **必须补齐的条件**：
  1. **A3/M4 无 CLI 直读盲区**：在 GitHub 网页直接浏览仓库、或不能执行 CLI 的只读审查者/云端 Agent，点进 `docs/` 无法一眼看到当前生效决策、开放任务和完成日志，PR 评论也不服务于默认分支的日常浏览。须明确静态页发布或轻量的标准只读视图命令（如 `docaxioms view`），并在 `docs/README.md` 明示无 CLI 时的阅读代价（A6）。
  2. **目录级可达性不能无条件放行**：现有 `src/check.mjs:466-468` 只把目录链接展开为 `${path}/README.md`。定稿 L298 改为“链接条目目录即视为目录下所有文件可达”，若不加限制，孤立杂文件也能过可达性门禁，削弱 A3/M4。条件是：**仅对受 schema 校验的条目目录授予目录级可达，且目录内每个文件必须通过对应条目结构校验**。
  3. **源码双模式兼容**：`src/check.mjs:147-206`（`decisionRows`）、`238-256`（`descriptionDocs`）、`305-319`、`438`、`483-508` 及 `src/garden.mjs:44` 均硬编码了单文件假设，实施时需同时兼容 `minimal`（单文件）与 `full`（目录条目）。

1. **显式 pin 应为 gate；我修正首轮立场。** 作者显式声明的谓词是“目标切片与所存摘要一致”，它精确、可检查，与 code pin 同构；“下游散文仍然正确”则没有被保证（A6、M2）。现有实现已经允许 pin Markdown 文件，并统一作为 gate。传播候选、语义判断继续做 aid。机制级别与本仓库的阻断政策分开：AD-7 下，摘要变化仍只报告，缺失或越界目标属于路径阻断。[实现](src/check.mjs:479)、[本仓库边界](test/self.test.mjs:31)

2. **剥注释与安全截断只部分一致。** 剥除 pin 元数据能避免“刷新摘要导致下游失配”，但不能证明 B 已复核。还需要分别跟踪正文输出、依赖定义和处置状态：依赖的增删、改指向不能随注释一起被忽略。对 `A → B → C`，只有 B 针对当前输入完成处置、C 消费的 B 切片未变，且 C 的其他入边均已处理，才能截断这条传播路径。静态检查可以让 C 的直接 pin 保持匹配，但不能据此宣称整条链已复核。

3. **是否需要证据，取决于承诺。** 若只承诺摘要一致，可以承认复核靠注意力；若要报告“已复核”并据此截断，就需要显式处置。最小记录是：**上游差异摘要、下游切片及依赖摘要、责任人、处置结果；无需改文档时写理由**。差异变化即失效，按变更组登记即可。普通提交信息不天然满足绑定要求；首版无需签名。记录也只证明有人声明处置，不证明判断正确。现有 `pin --write` 仅刷新摘要，不能充当这份证据。[实现](src/pins.mjs:324)、[G16 提案](research/全流程文档系统方案.md:262)

4. **“只改一处”成立于单个事实及其机械派生物。** 任务状态只维护一次，可以生成任务索引、计数；代码事实、owner 决策和任务状态仍各有权威来源。一次任务关闭可以成为统一处理入口，汇集这些变化并列出待办，却不能从“任务完成”推出行为描述已经正确，也不能自动决定阶段焦点。M3 要求每项事实有一个维护位置，不要求整个仓库只有一个根；K1 历史也不能随现状重写。

5. **反射弧适合作为处理流程的比喻，不能直接推出执行权限。** 自动动作应同时满足：规则明确、输入完整、写入范围获授权、结果可机械验证、风险可接受；仅确定或可逆都不充分。退役是否成立、旧链接应改指哪里仍可能需要判断。图也不必整体无环：导航允许环，散文复核环可成组报告，按拓扑执行的生成子图才须无环。“习惯化”应落实为同一刺激去重、同一下游合并原因、有效处置后消警；统计用于改进规则，不能因反复失败自动降低 gate。

6. **首版收敛为四项。**

   | 必须项 | 谓词与级别 | 复用机制 |
   |---|---|---|
   | 显式文档 pin | 目标有效、切片摘要匹配；**gate** | `inspectPins()`、`verifyPins()`；先沿用文件／行段 |
   | 只读影响报告 | 沿登记边列出直接失配、间接候选和触发路径；**aid** | pin、决策落点、Git 差异、`codeToDocs`；普通链接只服务导航与断链 |

## 2. 修订引入的新问题（无 P0/P1）

- **P2-1｜第 761 行与第 770 行关于“删掉替换记录如何被看见”前后矛盾，且漏提 profile schema 同步**
  - **出处**：第 `734, 761, 770, 850` 行（对照 `src/profile.mjs:41-63`）。
  - **问题**：第 761 行规定“生成元数据（`core`、**替换记录**）不比较”，不会出现在“待 owner 确认”里；但第 770 行又写“agent 也能直接改掉判据，比如改 profile、**删掉替换记录**。‘待 owner 确认’只能让这些被看见”。若不比较替换记录，agent 同时删掉替换记录和 `.project.md` 时，`onboard` 输出里看不见痕迹。此外往 `docaxioms.json` 写入替换记录键需同步加入 `src/profile.mjs` 的 `SCHEMA`（否则触发 G01 未知键报错）。
  - **改法**：让 `onboard` 固定输出一行替换记录计数摘要（有 Git `HEAD` 时还可核对 `HEAD` 中被替换的同名文件是否仍在记录中），或将第 770 行改为“删掉替换记录需靠 Git 差异审阅发现”；第 850 行补一句更新 profile schema。

- **P2-2｜第 726 行“嵌套入口纳入可达范围”与第 754、765 行不一致**

  - **改法**：将第 726 行改为“只纳入预算和 `@` 导入检查（第 3 项）的范围”。

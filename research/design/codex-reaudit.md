## 三、依赖图方案自身的问题与遗漏

以下是设计文本的问题或实现前置缺口，**不是已经实现的新功能回归**。

### 1. “研究→任务（已有、高精度）”不符合源码

**出处：图:30、78、88-89。判定：过时事实。**

当前实现没有研究到具体任务的真实链接解析，更没有任务身份和关联数量，只检查计划开放段是否含研究文件名。本次已复现子串误放行和编码链接误拒绝。

应先修 A-8：minimal 可从计划中的真实研究链接建关系；full 若采用研究页链接任务，则须定义新的来源、解析及开放状态合同。两种模式不能笼统写成同一条现成精确边。

证据：`src/check.mjs:523-534`。

### 2. 标题改名与“唯一同哈希迁移”的承诺不相容

**出处：图:77。判定：新问题。**

当前 `passage()` 的章节切片包含标题行；显式锚点切片也包含标签。仅把 `# Old title` 改为 `# New title`，正文完全不动，摘要仍改变。本次探针已确认。

应先定义定位标识与内容摘要的边界，或收窄自动迁移承诺。不能直接沿用行段 `moved`，声称标题改名后仍会找到相同摘要。

证据：`src/markdown.mjs:44-48、75-76`、`src/pins.mjs:77-88、179-200`。

### 3. 只补独立锚点正文，不足以满足“唯一解析”

**出处：图:77、82、118。判定：新问题。**

重复 `<a id="x">` 目前静默保留第一处；标题锚点和显式 ID 冲突时，`passage()` 优先取标题。本次探针确认重复 ID 返回第一块。

应让锚点索引保留候选及位置，遇到冲突明确失败；同时定义独立标签关联正文的范围。

证据：`src/markdown.mjs:67-77、150-155`。

### 4. 下游消费段落的作用域尚未定义

**出处：图:27-28、65、77-78。判定：需修改。**

现有 pin 知道“哪个文件哪行注释依赖哪个源切片”，但没有明确记录这条 pin 属于下游哪个段落。若直接按文件建图，A 的独立段落依赖 B、B 又依赖 A 的另一独立段落，就可能被误判为环。

应先定节点粒度、pin 的消费范围及嵌套归属，再承诺精确的段落传播和环检测。

证据：`src/pins.mjs:115-121、204-210`；章节范围见 `src/markdown.mjs:44-48`。

### 5. 环的规则内部不一致

**出处：图:40、77、128。判定：需修改。**

一处说 pin／生成器的依赖环要拦截，同时允许散文复核环成组报告；后面又把“成环”统一列为 gate。

应明确：生成执行图必须无环；散文 pin 环选择拒绝，或按强连通分量复核。两种合同不能并存。当前源码尚无图或环检测，见 `src/pins.mjs:115-213`。

### 6. 剔除 pin 注释后，还须比较依赖定义

**出处：图:97、102-107。判定：需修改。**

删除、增加或改指向一条 pin，可以保持去注释后的正文摘要不变；当前 `inspectPins()` 只枚举候选中仍存在的注释，无法发现被删除的依赖。

因此应分别比较 B、C 两侧的正文输出和依赖定义。图:107 的“增删 pin 触发自身复核”需要真实检测来源，不能只靠当前 pin 是否匹配。

证据：`src/pins.mjs:115-121`、`src/markdown.mjs:92-100`。

### 7. “中游已复核”仍缺可观测的判据

**出处：图:65、93、104-112。判定：需修改。**

“不设日常复核表单”可以是合理取舍，但此时工具只能机械判断摘要匹配、仅刷新摘要等状态，不能把它当作“已复核”再承诺整链截断。

应二选一：

- 普通项目只承诺摘要与影响候选，报告中保留语义复核靠注意力的边界；
- 需要可追踪“已处置”时，使用与 G16 共用、绑定当前差异和依赖身份的记录。

记录证明的是责任人的处置声明，仍不证明语义正确。证据：`src/pins.mjs:324-349`、B:262-268。

### 8. URL 之外文本相等，不能证明改链没有语义变化

**出处：图:58、80。判定：新问题。**

`withoutLinkTargets()` 会让 `[policy](policy-v1.md)` 和 `[policy](policy-v2.md)` 比较相等；本次已实跑确认。它只证明 URL 以外的文本未变。

自动改链须限定为已授权、无歧义的“同一对象从旧位置移到新位置”。选择接替规范、把旧记录指向新版政策，仍可能改变指涉，不能由这个比较器授权。

证据：`src/markdown.mjs:181-205`、`core/GUIDE.md:41`。

### 9. 退役还要修迁移文件自身的相对出链与 pin

**出处：图:80、89。判定：新问题。**

例如 `docs/research/r.md` 中的 `../design.md`，迁入 `docs/history/research/r.md` 后，会从 `docs/design.md` 变成 `docs/history/design.md`。相对 pin 也有同样问题。

而当前链接和 pin 检查在归档后不再扫描该文件，所以绿灯可能漏过错误：

- `currentDocs` 排除 history/core：`src/check.mjs:151-154`；
- 链接检查只扫 `currentDocs`：`:361`；
- pin 检查也只扫 `currentDocs`：`src/pins.mjs:117`。

应增加迁移专项验收，检查迁移前后引用目标身份，包括入链、出链、锚点和相对 pin；不能以现有门禁代表“全仓引用正确”。

### 10. 普通链接迁移与 K1 pin 迁移不能混为一谈

**出处：图:80、89；B:252。判定：需修改。**

pin 路径存在 HTML 注释里，不属于 history／G13 允许修改的链接 URL 区间。迁移被 pin 的文档后，只改 Markdown 链接会留下失效 pin；直接修改 K1 中的 pin，又越过记录冻结合同。

应明确现行文档如何重定向 pin，以及 K1 中的依赖如何保留和解释，不能把所有引用统一批改。

证据：`src/pins.mjs:105-111`、`src/markdown.mjs:176-205`。

### 11. 关闭一个任务，不足以无条件退役关联研究

**出处：图:88-92。判定：新问题。**

若开放任务 A、B 共用研究 R，关闭 A 就归档 R，会使 B 仍需要的资料退役。当前实现没有一对一约束，也不会在 R 离开开放研究目录后检查剩余任务关系。

应规定：研究只允许一个开放任务所有者并受检，或者在无剩余开放依赖、仍有效内容已迁给所有者后才退役。否则只解除本次关联。

证据：`src/check.mjs:529-534`、`core/GUIDE.md:36、41`。

### 12. 自动写入必须发生在最终候选形成之前

**出处：图:53、64、88-92。判定：需修改。**

图:92 的“同一个候选再验收”正确，但“终审时触发”仍可被理解为接收端验收期间生成、迁移和改链，从 T 产生 T′。

应写成明确顺序：

> 工作树命令完成写入和必要处置 → 形成最终 C/T → 正式验收只读重算、比较和签发。

G20 不一致时拒绝或返回待修，不修改已绑定候选。该合同来自 B:349、510-513。

### 13. Git 共改统计不能直接决定升格

**出处：图:69、95。判定：需修改。**

“提醒后文档是否改字”只能作为候选信号：无关润色也会计入，正确的“无需改文档”反而没有改字。它既不是误报率，也不足以满足 AD-7 的“值得改文档的发现”。

应保留人工归因及相关变更登记。图:95 的“命中率高的升格”应改为“据此提出收窄、删除或升格建议，经 owner 决定”。

证据：`docs/decisions.md:12`、`core/GUIDE.md:62`。

### 14. 首个生成索引不必等待 full 迁移

**出处：图:79、130。判定：不再需要这项硬依赖。**

现有决策表已有 `decisionRows()`，可以先从它生成索引、验证最小 G20。目录式决策及状态生成规则是独立决策，不能绑住首个生成物试点。

证据：`src/check.mjs:205-263`。

## 一、结论速览

- **定位**：三份报告的判断基本一致，也都成立。docaxioms 是本地、确定性的文档完整性门禁；和规格驱动框架（Spec Kit、OpenSpec、Kiro）是上下游关系；和 AI 托管文档（Mintlify、Dosu、DeepWiki）在 A0 上立场相反。
- **源码缺陷**：B 和 C 报的缺陷，大多有运行见证。去重后共 15 项（第二节），每项都在这一节写明了判定。最有价值的是这几项：
  - paths 门禁扫描范围错；
  - history 比较可被绕过；
  - 链接能指向仓库外；
  - profile 键名拼错会让门禁静默失效；
  - 显式配置的文件缺失时，整次检查中止。
- **A 的 P0 不成立**：A 列为 P0 的“`src/index.mjs` 缺失”对当前 HEAD 不成立。文件存在，打包后独立安装可以 import，共 19 个导出。
- **事实错误**：三份报告各有一些（第七节），引用时以本文为准。

## 三、迭代候选（三方讨论后的排序）

### 第一批：门禁与自身契约不符，成本低
1. 缺陷 4：profile 校验。三方都主张放最前。
2. 缺陷 1：paths 扫描作用域。
3. 缺陷 3：仓库内路径解析与越界。
4. 缺陷 2：history 只比较 URL 以外的内容。
5. 缺陷 5：显式配置的文件缺失时，给诊断而不是中止。
6. 缺陷 10 中的 `#L` 漏检、选项误报和作用域未命中。
7. 缺陷 7：换行契约，先定方案。
8. 缺陷 6：默认决策前缀，附迁移说明。
9. 缺陷 8、9、15 作为后续小修。

### 第二批：小而确定的可用性改进
- **结构化输出**：给 `--json` 的每条 finding 加稳定的 code 字段，能定位时再加 file/line；同时加上缺陷 11 的 checked 计数。`--json` 现在已经输出对象数组，B 说它是“纯文本串数组”不对。全局检查的结果没有单一行号。SARIF 等出现真实的集成需求再做。checked 计数只能用来发现空跑，不能当作 AD-7 的分母（AD-7 要的是 10 次相关变更）。
- **可选参数 `--require-base`**：缺比较基线时把 note 变成失败，默认行为不变。三方都认为它与 A6、A7 不冲突，但不能借它绕过 AD-7。要写明它的边界：在主分支上 push 时 base 等于 HEAD，仍然没有可比较的内容。
- **缩短必读阅读链**：`templates/AGENTS.md` 把整份 GUIDE 列为无条件必读，而 GUIDE 末尾的 profile 字典有 1,983 B。先改模板，只在改文档或改配置时才读相应部分；或另外提供一个可选的按需 SKILL.md。拆字典往后排，收益要用真实会话做 A/B 实测。
- 缺陷 12、14。

### 第三批：等需求或实验数据
- **命名区域 pin**（参考 mdBook 的 `ANCHOR:` / `ANCHOR_END:`）：可选启用，区间内容一变照样失败。**不要默认剥除行尾空白**：codex 实跑出反例，Python 多行字符串里的行尾空白是数据。
- **薄 GitHub Action**：降低非 JS 仓库的接入成本。先验证有人要，再评估单二进制。单二进制可以照抄 OpenSpec 和 markdown-magic 的 `bun build --compile` 流程；但 docaxioms 读资源依赖 `import.meta.url`，projectChecks 又是动态 import，打包后能否正常工作还没验证。
- **init 只读探测**：发现 package.json、Makefile 时只打印建议配置，不写文件；另做一个 demo 故障样本。
- **目录式决策**（参考 log4brains 的“日期-slug”单文件）：可以减少并行时撞行，但独立文件仍可能撞 ID、争抢索引页和落地点。冲突频率目前没有数据。
- **日志防删改的 aid**：日志属于 K1 记录，受 A5 约束，加这个 aid 有现成依据。
- **写入类命令或基线功能**，如果以后要做：
  - 借鉴 Dosu CLI 的 `--confirm` 协议：没有 TTY 时只给预览，`pin --write` 也适用；
  - 借鉴 DocGuard 写基线前的两道守卫：不和增量模式混用；存在降级 note 时拒绝写入。
- **AD-7 外部实证**：在另一个真实项目里以报告模式至少跑 10 次相关变更，拿到 3 条值得改文档的发现。这是所有门禁升格的前提，也是目前最缺的数据。

### 不建议做
- **常驻 MCP Server**（A 的 P2、C 的候选 8）：本地 CLI 加上代理自带的 shell 已经够用，常驻工具描述会占用每次会话的上下文（OpenSpec #319 有讨论）。同为本地 CLI 的 OpenSpec 也没做；提供 MCP 的主要是没有本地文件系统的云端 SaaS。
- **照搬 DocGuard**：数十个与框架绑定的校验器、成熟度评分、`diagnose --auto` 自动改文档。会违背 A7（误报面变大）和 A0（迎合代码）。
- **任何由代码驱动、自动改写文档的闭环**（Mintlify Autopilot、Dosu Auto-Accept、Swimm Auto-sync 一类）：违背 A0。

| 做法 | 来源 | 借鉴什么、不借鉴什么 |

| “脚本只度量不评判，代理只评判不度量” | Marmelab 2026-09（已核实原话） | 正对应 check 与 garden 的分工，可用作对外表述 |

| 现行真相与进行中的变更分目录 | OpenSpec 的 specs/ 与 changes/ | 留给目录式决策和阶段卡做参考 |

**外部证据怎么用、用到哪为止**（均已核对原文）：

- **上下文文件的成本**：
  - Gloaguen 等，arXiv 2602.11988，作者 5 人，当前为 v3：含冗余概览的上下文文件让步数增加 2.45 到 3.92，成本增加 19% 到 23%，差异显著；成功率没有显著变化。
  - Lulla 等，arXiv 2601.20404：精炼的 AGENTS.md 让中位耗时下降 28.64%，中位输出 token 下降 16.58%（p<0.05）。
  - 两篇合看：精简有效，冗余有成本。但测的都是一次性任务，不能直接换算成 docaxioms 的成本。
- **路径和指令过期**：
  - Ghimire 与 Damian，arXiv 2611.29916：代码移动后，39% 的陈旧路径长期没人修；而在未命中的路径里，只有 2.2% 是真错误。路径门禁有必要，豁免和降噪同样重要。
  - Mehtiyev 等，arXiv 2611.09802：只测了 3 条过期指令，其中 1 条有显著开销。只能从机制上说明价值。
- **文档漂移**：De Michele 与 Tantithamthavorn，arXiv 2610.27381：63.2% 的 AI PR 改了代码却没动文档。后续修复率高 8.6% 到 11.7%，这是相对增幅，绝对差只有 1.2 到 1.7 个百分点；论文只主张相关，不主张因果。
- **理由的价值**：Chakrabarti，arXiv 2608.11095：CLAUDE.md 会持续膨胀，增幅达 226%。给指令写上理由后，安全删减率从 6.0% 升到 17.1%，合规率高 6.6 个百分点（p=0.003）。支持 A8。
- **审查不能交给 LLM**：Yang、He 与 Zhou：超过 70% 的指令文件 PR 没有实质性的人工审查，AI 自动审查只召回了人类关注点的 1.3% 到 3.9%。
- **误报门槛**：Christakis 与 Bird（2016）：90% 的开发者只接受不超过 5% 的误报率。支撑 A7。

## 五、分歧与待 owner 决定的问题

- **换行（缺陷 7）**：
  - agy：core 哈希和 history 比较统一归一化为 LF。
  - codex：core 用 init 写入的 `.gitattributes` 锁定 LF，保留“按字节认文件”；只有 history 比较做归一化。
  - Claude 倾向 codex：core 哈希是 A4 意义上的版本身份，从“字节一致”改成“文本一致”属于契约变更，需要 owner 同意并写迁移说明。init 写 `.gitattributes` 不进 core/，不违反 AD-2。
- **被 gitignore 的目标（缺陷 13）**：
  - codex 主张允许构建产物，保留“工作树里存在即可”的现有语义；
  - agy 主张默认报错，再为构建产物开豁免。
- **决策怎么退役**：
  - 背景：提交 86dffc1 删除了一条从未发布的更名决策，提交说明里讲了原因。GUIDE 第 14 行管的是决策“被推翻”时改状态、保留旧行（依据 A5），这次不属于这种情况，所以不能判为违规，也不需要为了编号连续去恢复它。
  - 暴露的问题：代码接受 `withdrawn` 状态，GUIDE 却没写“不再适用的决策”该怎么退役。
  - 需要二选一：在 GUIDE 补一条退役规则（改状态、保留原文），或者明确允许删除未发布的决策。
  - 撤回的论证：我在初稿里说“决策行属 K2，A5 管不到”，codex 和 agy 都指出这是错的，GUIDE 第 14 行就是按 A5 保留被推翻的旧行。
- **非 Markdown 落地点（缺陷 9）**：去源码里查 ID，还是直接报错。
- **拆 GUIDE**：agy 主张不拆；codex 主张拆，但往后放，新页也纳入 core pin。共识是先改模板的阅读指令。

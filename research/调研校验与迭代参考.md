基线：提交 8336bed（`0.1.0-alpha.0`），2026-11-25。
来源：`research/sources/` 下的三份调研报告（下称 A：《Docaxioms评估与竞品对比》；B：《Docaxioms 竞品对标与迭代调研》；C：《Docaxioms 与同类工具及文档系统对比调研报告》，第七节单独处理）。
校验方式：codex 在仓库副本中实跑复现源码断言（42 个实验、Node 22，现有 102 项测试全过）；agy 联网逐条核对论文、竞品与外部事实；Claude 读源码交叉核对并主持讨论。三方结论不一致处单列在第五节。
原始核验记录、讨论意见与 codex 的复现脚本和日志在 [fact-check/](fact-check/codex-findings.md)（该目录与 `research/sources/` 都在 `docaxioms.json` 的 `ignore` 中：实验样本故意含有失效路径，原始报告则会提到其他项目的路径）。

本文只是参考，不是决定。下面每一项要落地，都要由 owner 决定，并按 AD-7 的节奏推进。

## 一、结论速览

- 两份报告对定位的判断基本成立：docaxioms 是本地、确定性的文档完整性门禁，和规格驱动框架（Spec Kit、OpenSpec、Kiro）是上下游关系，和 AI 托管文档（Mintlify、Dosu、DeepWiki）在 A0 上立场相反。
- B 推测的 7 项源码缺陷**全部有运行见证**（5 项 CONFIRMED，2 项 PARTIAL），这是两份报告里最有价值的部分。
- A 列为 P0 的“`src/index.mjs` 缺失”在当前 HEAD **不成立**：文件存在，打包后独立安装可以 import，19 个导出。A 用的是旧 zip 快照，只能判它对当前 HEAD 不成立。
- 两份报告各有若干事实错误（第六节），引用时以本文为准。

## 二、已实跑确认的缺陷（优先修）

| # | 缺陷 | 判定 | 根因与修法要点 |
|---|---|---|---|
| 1 | paths 门禁扫到日志、计划、研究、旧决策 | CONFIRMED | `src/check.mjs:383` 用的是 `p.currentDocs`，与第 367 行注释（只查现行描述）不符。改用 `descriptionDocs(p)`，再**补回阶段卡**：`descriptionDocs` 排除了阶段卡，而阶段卡里的路径仍应检查。不要为每类文档单独加豁免 |
| 2 | history 比较：多行 link title 能绕过；修引用式定义或平衡括号 URL 会误报 | CONFIRMED | `bare()` 用 `/\]\([^)]*\)/g` 擦除括号内容。改为在 AST 上只擦除 link/definition 的 URL 区间，title 和正文照常比较。不能声称“用了 AST 就零绕过” |
| 3 | 模板默认决策前缀 `D` 会把正文里的 D1、D2、D3 当成决策号 | CONFIRMED | 新模板改用 `D-` 一类的前缀；已用 `D` 的项目不会自动修好，要写迁移说明，不能静默改写 owner 的记录。B 说“高频误报、用户会关掉门禁”，目前没有数据 |
| 4 | 换行：Git `core.autocrlf=true` 检出后，4 个 core 文件哈希不匹配，update 拒绝，追加合法勘误也报失败 | PARTIAL（Git 场景已实跑，Windows 实机未测） | 仓库没有 `.gitattributes`。只有 `src/pins.mjs:58` 做了 CRLF 归一化。修法有分歧，见第五节 |
| 5 | 开放研究与计划的关联用文件名子串匹配（`alpha.md` 能放过 `a.md`） | CONFIRMED | 只在计划的开放段里按真实链接目标判定。不能直接取整篇文档的链接，否则已关闭段的链接也会算进去 |
| 6 | 落地点不是 `.md` 或是目录时跳过反向引用检查；链接带 `?query` 时找不到文件；以 `/` 开头的链接拼成错误路径 | CONFIRMED（行为） | 剥离 `?query` 属于明确的 bug。非 Markdown 落地点和前导 `/` 的含义，要先定契约再修 |
| 7 | 以编程方式调用 init 时，路径带尾斜杠会让返回名少掉首字符；空文件按 1 行计 | PARTIAL | 磁盘上的文件不受影响，只是返回名错。NIT，顺手修即可 |

另有两处实跑发现，B 没有列为缺陷：

- **profile 不做校验**：键名拼错（`commmands`）时，对应门禁直接静默失效，退出码 0。这属于 A6 意义上的静默降级，三方一致建议**提到第一优先级**。
- **整文件 pin 写入后不显示预览**：只有带行范围的 pin 会打印前 12 行。

## 三、迭代候选（三方讨论后的排序）

### 第一批：成本低，修正门禁与自身契约不符的地方
1. profile 已知键、类型、正则的早期校验。先约定扩展键的写法（如 `x-*`）以及 projectChecks 的兼容方式。
2. 缺陷 1：paths 扫描作用域。
3. 缺陷 2：history 只比较 URL 以外的内容。
4. 缺陷 4：换行契约（先定方案，见第五节）。
5. 缺陷 3：默认决策前缀，附迁移说明。
6. 缺陷 5、6（`?query`）以及缺陷 7，作为后续小修。

### 第二批：小而确定的可用性改进
- **可选参数 `--require-base`**：缺少比较基线时，把 note 变成失败。默认行为不变，仍只打 note。三方都认为它与 A6、A7 不冲突，但不能借它绕过 AD-7。还要写明它的边界：在主分支上 push 时，base 等于 HEAD，仍然没有可比较的内容。
- **给 `--json` 每条 finding 加稳定的 code 字段，能定位时再加 file/line**。注意 `--json` 现在已经输出对象数组，B 说它是“纯文本串数组”是错的。全局检查的结果没有对应的单一行号。SARIF 等出现真实的集成需求再做。
- **缩短必读阅读链**：`templates/AGENTS.md` 把整份 GUIDE 列为无条件必读，而 GUIDE 末尾的 profile 字典有 1,983 B。两种做法：
  - 先改模板，不动 core/：只让代理在改文档或改配置时才读相应部分；
  - 或另给一个可选的按需 SKILL.md（发现层约 100 tokens）。

  把字典拆出 GUIDE 的方案往后排（见第五节）。收益要用真实会话做 A/B 实测，不能直接套论文里的数字。

### 第三批：等需求或实验数据
- **命名区域 pin**（参考 mdBook 的 `ANCHOR:` / `ANCHOR_END:`）：可选启用，区间内容一变照样失败。**不要默认剥除行尾空白**：codex 实跑出反例，Python 多行字符串里的行尾空白是数据，剥掉会改变语义。
- **薄 GitHub Action**：降低非 JS 仓库的接入成本。先验证有人要，再评估单二进制。
- **init 只读探测**：发现 package.json、Makefile 时只打印建议配置，不写文件；另做一个 demo 故障样本。
- **目录式决策**（参考 log4brains 的“日期-slug”单文件）：可以减少并行时撞行，但独立文件仍可能撞 ID、争抢索引页和落地点；冲突频率目前没有数据。
- **AD-7 外部实证**：在另一个真实项目里以报告模式至少跑 10 次相关变更、拿到 3 条值得改文档的发现。这是所有门禁升格的前提，也是目前最缺的数据。

### 不建议做
- **常驻 MCP Server**：本地 CLI 加上代理自带的 shell 已经够用；常驻工具描述会占用每次会话的上下文（OpenSpec #319 有讨论）。B 和 agy 都反对，A 的建议在这里不成立。
- **照搬 DocGuard**：数十个与框架绑定的校验器、成熟度评分、`diagnose --auto` 自动改文档。这些会违背 A7（误报面变大）和 A0（迎合代码）。
- **任何由代码驱动、自动改写文档的闭环**（Mintlify Autopilot、Dosu Auto-Accept、Swimm Auto-sync 一类）：违背 A0。

## 四、值得借鉴的外部做法（经核实）

| 做法 | 来源 | 借鉴什么、不借鉴什么 |
|---|---|---|
| 入口文件约 100 行，只当地图用 | OpenAI Harness Engineering（2026-02，已核实原文） | 和现有 budgets 门禁一致；佐证缩短必读链的方向 |
| “脚本只度量不评判，代理只评判不度量” | Marmelab 2026-09（已核实原话） | 正对应 check 与 garden 的分工，可用作对外表述 |
| 报错里直接写修复指引 | OpenAI 原文（A 误把出处归给 Marmelab） | 适合加在 finding 的 code 字段旁；需要 owner 裁决的失败不能给出“自动改写”模板 |
| 按需加载的 SKILL.md（发现层约 100 tokens，正文少于 500 行） | agentskills.io（已核实）；OpenSpec v2.0 起全面采用 | 放在外围模板，作为可选项，不进 core/ |
| 命名注释锚点 | mdBook `ANCHOR:` | 只借“免疫行号平移”这一点；不借构建时自动覆写，否则旁边的说明文字会静默过时 |
| 用 pass / fail / inconclusive / skipped 区分结果状态 | DocGuard | docaxioms 的 note 已覆盖其中一部分；做 finding code 时可以参考 |

**外部证据怎么用、用到哪为止**（均已核对原文）：

- Gloaguen 等，arXiv 2602.11988，作者 5 人，当前为 v3：
  - 含冗余概览的上下文文件使步数增加 2.45 到 3.92，成本增加 19% 到 23%，差异显著；成功率没有显著变化。
  - 局限：测的是一次性修复 issue 的任务，不能直接换算成 docaxioms 的成本。
- Lulla 等，arXiv 2601.20404：
  - 精炼的 AGENTS.md 让中位耗时下降 28.64%，中位输出 token 下降 16.58%，p<0.05。
  - 中位输入 token 上升 3.41%，不显著。
  - 两篇合看的结论：精简有效，冗余有成本。
- De Michele 与 Tantithamthavorn，arXiv 2610.27381：
  - 63.2% 的 AI PR 改了代码却没动文档。
  - 后续修复率高 8.6% 到 11.7%，这是**相对**增幅，绝对差只有 1.2 到 1.7 个百分点；论文只主张相关，不主张因果。
- Christakis 与 Bird（2016）：90% 的开发者只接受不超过 5% 的误报率。这条可以支撑 A7 的门禁门槛。
- Mehtiyev 等，arXiv 2611.09802：只测了 3 条过期指令，其中 1 条有显著开销。只能从机制上说明路径和命令保持新鲜有价值。

## 七、报告 C 的增补

C 的基线同为 8336bed。它与 A、B 重叠的部分（history 正则、默认前缀 `D`、research 子串匹配、规则码、SARIF、单二进制、MCP）结论不变，下面只列新增内容。核验材料在 `fact-check/` 下的 codex3、agy3 文件和 codex3-lab 中。

### 新增缺陷的实跑结果

| C 编号 | 内容 | 判定 | 要点 |
|---|---|---|---|
| D-1 | 普通链接和决策落地点能用 `../` 指向仓库外；以 `/` 开头的链接拼成错误路径 | CONFIRMED | 带 fragment 时会真的读取仓外 Markdown；pin 已有越界检查，链接没有。C 给的 `/README.md` 例子实际是假通过，不是报错 |
| D-4 | 显式配置的 decisions / sections / research.items 文件缺失时整次 check 中止；`openUntil` 被当作正则 | PARTIAL | CLI 有顶层 catch，只打印 message，不是“未捕获崩溃”；但 `--json` 没有任何输出，也给不出逐项诊断。标题里的 `[`、括号会让切分出错 |
| D-5 | 链接、路径、pin 指向被 gitignore 的文件时，本地通过、干净 clone 失败 | PARTIAL | 现象成立，但 C 复现命令里的 hash 写错了；CI 先构建再检查也能通过。当前谓词只承诺“磁盘上存在” |
| D-6 | 独立成行的 `<a id>` 后隔一个空行，落地检查找不到正文 | PARTIAL | 锚点后紧接正文（不隔空行）也能通过，C 说“必须同一行”是错的；`span`、`h3` 的 id 不识别，属于支持范围问题 |
| D-8 | 提交 86dffc1 删除了第 5 号决策行 | 删除属实；“违规”不成立 | 见下文 |
| D-9 | `pin --write --file/--pin` 未命中任何目标时退出 0；`` `src/x.mjs#L10` `` 不查存在性；npm run 后接选项（如 --silent）时把选项当成脚本名；cd 加 && 的复合命令被跳过 | PARTIAL（四个现象都成立） | 有过期 pin 时会打印 stale 提示，并非“总是静默” |

**D-8 的定性**：GUIDE 第 14 行写的是决策“被推翻”时改状态、保留旧行（依据 A5）；这次是删除一条从未发布的更名决策，提交说明里讲了原因。所以不能判为已证实的违规，也不要求为了编号连续去恢复它。真正暴露的是**规范空缺**：代码接受 `withdrawn` 状态，GUIDE 却没写“不再适用的决策”该怎么退役。需要 owner 二选一：在 GUIDE 补一条退役规则（改状态、保留原文），或者明确允许删除未发布的决策。日志属于 K1 记录，给它加防删改的 aid 有现成依据，不必等这件事定下来。（初稿里“决策行属 K2，A5 管不到”这一论证，被 codex 和 agy 同时指出有误，已撤回。）

### 并入迭代清单

- **第一批**（门禁与契约不符）：
  - D-1：抽一个统一的仓库内路径解析函数，越界就报错。前导 `/` 定为仓库根，并写进契约；codex 和 agy 都主张定为仓库根，而不是直接报错。
  - D-4：显式配置却缺失的文件，改为在该检查项下给出一条诊断，不再中止整次检查。`openUntil` 按字面标题匹配；只加 escape 不够，还要保证匹配的是完整标题。
  - D-9：`#L` 行号片段先剥离再检查存在性；commands 跳过选项参数；`pin --write` 的作用域没命中任何目标时报错。命中了但已是最新时仍退出 0。复合 shell 命令不解析，并明确写明不支持。
- **第二批**：
  - 零匹配可见性：显式配置的规则命中 0 个对象时打 note，不用 aid；`--json` 给出 checked 计数，和稳定规则码一起改。没配置的规则、或本次合法的空集合，不提示。checked 计数只能用来发现空跑，不能当作 AD-7 的分母（AD-7 的分母是 10 次相关变更）。
  - D-6：空锚点隔一个空行后的段落，也算作它所指的 passage。
- **待 owner 定**：
  - D-5 的契约：codex 主张允许构建产物，保留“工作树里存在即可”的现有语义；agy 主张默认报错，再为构建产物开豁免。
  - D-8 引出的决策退役规则。
- **以后若做写入类命令或基线功能**：
  - 借鉴 Dosu CLI 的 `--confirm` 协议：没有 TTY 时，写命令默认只给预览，`pin --write` 也适用；
  - 借鉴 DocGuard 写基线前的两道守卫：不和增量模式混用；存在降级 note 时拒绝写入。
- **单二进制**：OpenSpec 和 markdown-magic 都用 `bun build --compile` 出过免 Node 的二进制，有现成样板可抄。但 docaxioms 读资源依赖 `import.meta.url`，projectChecks 又是动态 import，打包后能否正常工作都没验证，所以排序不变。
- **仍不做**：常驻 MCP（C 的候选 8）。理由同第三节；C 自己引用的上下文成本研究也支持这个判断，而且同为本地 CLI 的 OpenSpec 也没做。

### C 新挖到的外部证据（已核对原文）

- Ghimire & Damian（arXiv 2611.29916）：
  - 开源上下文文件里，代码移动后有 39% 的陈旧路径长期没人修；
  - 在未命中的路径里，只有 2.2% 是真错误。

  这说明路径门禁有必要，豁免和降噪也同样重要。
- Chakrabarti（arXiv 2608.11095）：
  - CLAUDE.md 会单调膨胀，增幅达 226%；
  - 给指令写上理由后，安全删减率从 6.0% 升到 17.1%，合规率提高 6.6 个百分点（p=0.003）。

  这支持 A8：决策要写明理由。
- Yang、He 与 Zhou：
  - 超过 70% 的指令文件 PR 没有实质性的人工审查；
  - AI 自动审查只召回了人类关注点的 1.3% 到 3.9%。

  这说明不能用 LLM 直接审查来代替确定性门禁。
